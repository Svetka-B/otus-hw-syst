## Описание проекта
Настройка конфигурации веб приложения под высокую нагрузку. 

Цель работы: 
Научиться развертыванию серверов веб-приложения, способного выдерживать высокие нагрузки и обеспечивать отказоустойчивость, используя Terraform и Ansible

## Описание/Пошаговая инструкция выполнения домашнего задания:

Используйте terraform и ansible роль для развертывания серверов веб приложения под высокую нагрузку и отказоустойчивость.

1) Создать несколько инстансов с помощью терраформ (2 nginx, 2 backend, 1 db);
2) Развернуть Nginx и Load balancer от Yandex;
3) Развернуть бэкенд способный работать по Uwsgi/Unicorn/PHP-FPM и базой данных при помощи Ansible;
4) Развернуть GFS2 для бэкенд серверах, для хранения статики;
5) Развернуть СУБД для работы бэкенда при помощи Ansible;
6) Проверить отказоустойчивость системы при выходе из строя серверов backend или nginx.

## Подготовленная инфраструктура

В лабораторной работе развернулы Yandex NLB + 2 nginx + 2 backend + PostgreSQL
- nlb-1 — внешний Yandex Cloud Network Load Balancer;
- nginx-1 — первый nginx-хост;
- nginx-2 — второй nginx-хост;
- backend-1 — первый backend-хост с Django-приложением;
- backend-2 — второй backend-хост с Django-приложением;
- db-1 — хост с PostgreSQL.

На nginx-1 и nginx-2 поднимаются nginx и keepalived. Nginx проксирует запросы на backend-серверы, keepalived обеспечивает отказоустойчивость между двумя nginx-хостами через виртуальный IP.
Снаружи трафик приходит на внешний Yandex Cloud Network Load Balancer, который отправляет запросы на nginx-1 и nginx-2 по 80 порту.
На backend-1 и backend-2 работает Django-приложение через uWSGI. Django‑приложение в этом проекте — это простой веб‑сайт, который отрисовывает страницы и ходит в PostgreSQL, чтобы получать и сохранять данные.
База данных вынесена на отдельную машину db-1 с PostgreSQL.

## Ход работы

Запускаем манифесты для создания ВМ через Terraform. После создания ВМ, их адреса нужно добавить в inventory Ansible. Далее запускается playbook site.yml, который назначает роли хостам:
- common — назначается всем хостам, выполняет базовую подготовку;
- postgresql — назначается на db-1, устанавливает и настраивает PostgreSQL;
- backend — назначается на backend-1 и backend-2, разворачивает Django-приложение и uWSGI;
- nginx — назначается на nginx-1 и nginx-2, устанавливает nginx и загружает конфиг с upstream на два backend-сервера;
- keepalived — назначается на nginx-1 и nginx-2, настраивает VRRP и виртуальный IP.

Во внешнем NLB целевая группа настроена на nginx-1 и nginx-2. В nginx используется upstream на два backend-хоста.
